# 자연어 세부 플로우 검증 · 2026-10-08

사용자 요청: 자연어 설명을 세부 노드로 구성하고, 여러 이미지의 공통 처리와 그룹·스타일·개별 결과 구조를 반영한다.

## 실제 GPT 구성

공개 테스트 사이트에서 사용자별 GPT 세션을 통해 실제 구성을 요청했다. 입력은 기존에 생성한 향수·스킨케어 예제 사진 두 장이다. 이미지 픽셀은 구성 요청에 포함하지 않고 이미지 이름·인덱스, 선택 범위, 스타일과 실제 명령 목록만 전달한다.

요청: 사진마다 독립적으로 누끼 → 베이지 스튜디오 배경 → 부드러운 조명 → 선명도 개선. 연출 명령 필수, 제품 보존, 합성 없이 개별 결과를 같은 폴더로 묶기.

관찰 결과: 기존 4노드 플로우를 유지하면서 새 그룹에 11개 노드가 추가됐다. 새 입력 노드는 하나이며 사진 두 장을 유지한다. 실행 작업은 edit 3개와 upscale 1개, 최종 preview는 하나다. 구성 화면에서 사진 2장 × 작업 4단계 = 예상 이미지 요청 8회를 표시했다.

연출 명령: /REMOVEBG, /NEWBG /STUDIO /PRODUCTSHOT, /STUDIOLIGHT /SOFTLIGHT /PRODUCTSHOT, /HDREAL /NATURAL. 각 단계에 제품 형태·색상·라벨 보존 지시가 따로 생성됐다. 후속 공통 스타일은 배경 제거 다음 단계에만 연결됐다.

실제 GPT로 확인한 것은 플로우 구성이다. 이 검증에서 실제 이미지 생성 8회를 실행하지는 않았다. 실행 전달·사진별 격리·투명 배경 해제·결과 폴더는 자동 테스트로 검증했다.

## 최종 검증

- `npm run build`: 성공, TypeScript 통과.
- `node --test --test-reporter=dot tests/*.test.cjs bridge/tests/*.test.js`: 100개 통과, 종료 코드 0.
- 신규 회귀 테스트: 두 사진의 개별 단계 실행, 두 입력의 합성, 공통 스타일 전달, 잘못된 배치/참조 혼합과 입력 인덱스 거절, 픽셀 없는 구성 문맥, 상세 이름의 백업·템플릿 보존, 후속 단계 스타일 범위.
- 기존 동시 구성·취소 테스트의 실행 환경을 실제 새 의존성에 맞췄다. 단일 제출·취소 후 적용 방지·입력 및 출력 모드 보존 검증을 유지하고 기존 입력을 변경하지 않는 검증을 추가했다.
- 실제 화면에서 공통 스타일 재적용 성공, 11개 상세 이름 유지, 실행 순서 유지와 예상 8회 표시를 확인했다.
- 노드 위치와 관계없이 단계 목록은 연결의 위상 순서를 사용한다.
- 320/390/768/1280px: 문서 너비와 뷰포트 너비 일치, native select 0개, 단계 목록 11개. 최소 단계 버튼 높이 82px 이상.
- `final-desktop.png`: 실제 GPT 구성과 세부 작업 패널. `configure-{320,390,768,1280}.png`: 최종 빌드의 반응형 캡처.
- 브라우저 콘솔 오류 0개. 공개 링크 HTTP 200.

중간 네이티브 스크롤 캡처가 뷰포트 설정을 따르지 않아 해당 잘못된 모바일 캡처는 제거했다. 위 반응형 캡처의 실제 PNG 너비는 각각 파일명의 너비와 일치한다.

## 구현 검토

구성 규칙과 검증은 Bridge, 구성 문맥과 입력 연결은 workflow-plan, 단계 목록은 workflow-plan-panel에 각각 둔다. 응답은 기존 프로젝트 백업 파서로 읽고 연결·입력 인덱스와 메타데이터를 검증한다. 새 의존성·타입 오류 억제·인증 우회는 없다. 기존 큰 page.tsx 전체 구조는 이번 범위에서 재작성하지 않았다.

Bridge를 반영하며 메모리 계정 세션이 초기화됐다. 이후 사용자 계정 연결 상태에서 실제 GPT 구성을 확인했다. Cloudflare 터널은 종료하지 않았다.
