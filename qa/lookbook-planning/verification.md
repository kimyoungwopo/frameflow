# 룩북 자연어 생성 오류 수정 — 2026-10-09

사용자의 정확한 요청:

> 남자모델, 여자모델을 만들고 모델이미지를 활용해서 사용자가 올린 코디를 모델이미지와 합치고 룩북처럼 여러 동작과 여러 각도 스트릿컷 같이 4개의 이미지가 나왔으면해 자연스럽게 나오고 텍스트는 들어가면 안되 그리고 모델의 얼굴이 변화가 없어야해

실제 실패를 재현했다. 초기 웹 로그에 TimeoutError, elapsedMs=120015 및
120016이 기록됐다. 이후 응답 파서의 실패 분기를 구분해 Bridge 로그의
`[planner] validation failed { reason: 'stream_size', node: null }`을 확인했다.
전체 SSE 응답의 1MiB 제한을 넘어 최종 플로우를 받기 전에 중단됐고,
자동 재구성도 전체 120초 제한에 도달해 일반 연결 오류로 표시됐다.

수정:

- 전체 Responses 스트림 제한을 8MiB로 조정했다. 최종 JSON 텍스트는
  기존 262,144 길이 제한(JS String.length)을 유지하고,
  노드/연결 수·종류·입력·DAG 검증도 유지한다.
- 빈 종료 output에 대한 fallback은 message 항목만 보관한다.
- 파서 오류에 원문을 포함하지 않는 원인 코드를 추가했다.
- 구성 요청은 같은 모델의 low reasoning effort를 사용한다.
  [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/reasoning)를 확인했다.
- TimeoutError는 JSON HTTP 424/provider_plan_timeout과 구성 시간 초과 안내로 반환한다.
- 운영 진단은 코드·노드 번호·요청 길이·HTTP 상태·소요 시간만 기록한다.
  인증정보, 사용자 프롬프트, 원시 응답은 기록하지 않는다.

재현 테스트:

600KiB reasoning 메타데이터가 중간 항목과 종료 응답에 포함된 유효한
워크플로우 스트림은 변경 전 provider_plan_invalid/stream_size로 실패했다.
변경 후 같은 스트림에서 유효한 그래프를 읽는다. 8MiB 초과 스트림과
길이 262,144 초과 최종 텍스트는 계속 거절한다. timeout 안내 및 low effort
요청도 각각 변경 전 실패/변경 후 통과하는 회귀 검증을 추가했다.
