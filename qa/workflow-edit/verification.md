# 기존 플로우 자연어 수정 · 2026-10-09

사용 방법: 그룹 또는 연결된 노드를 선택 → 입력·설정 → 자연어로 플로우 수정 → 수정안 확인 → 적용. 한 번 되돌릴 수 있다. 여러 플로우가 있을 때 대상 선택 없이 전체 프로젝트를 교체하지 않는다.

## 구현

- 기존 GPT 계획 엔드포인트와 사용자별 계정 세션을 재사용한다. Bridge와 Cloudflare 터널은 재시작하지 않았다.
- 선택한 그래프의 노드 ID·유형·프롬프트·스타일·입력 인덱스·연결을 보낸다. 이미지 픽셀, 캐시 결과, 결과 폴더와 인증 정보는 구성 문맥에 넣지 않는다.
- 유지되는 노드 ID와 이미지 입력을 이어 붙이고 선택한 플로우만 교체한다. 다른 플로우의 객체·연결·그룹과 결과 history는 유지한다.
- 수정안에는 설명, 추가·수정·삭제 개수, 연결에 따른 단계 순서, 예상 이미지 요청 횟수가 나온다. 노드 이름·설명 변경도 수정 개수에 포함한다.
- 적용 전까지 원래 그래프는 바뀌지 않는다. 변경된 작업의 미리보기 캐시는 비우고 이전 결과 폴더는 보존한다.
- 원본 객체 참조와 연결을 비교하여 수동 수정·프로젝트 전환·외부 연결이 생긴 오래된 수정안의 적용 또는 되돌리기를 막는다. 관계없는 플로우의 후속 변경은 보존한다.
- 대상은 한 그룹 또는 한 연결된 플로우이며 64노드·128연결, 입력 문맥은 기존 서버의 8,000자 한도를 따른다. 큰 문맥에서는 명령 카탈로그를 먼저 제외하며, 그래프가 여전히 너무 크면 작은 범위 선택을 안내한다.

## 실제 GPT와 화면 검증

검증용 새 프로젝트에 이전에 생성한 제품 예제 백업을 가져왔다. 입력은 향수·스킨케어·운동화 3장, 기존 결과는 한 폴더의 3장이다. 보존 여부를 확인할 별도 광고 플로우 4노드도 추가했다. 사용자의 기존 실작업 프로젝트를 수정하지 않았다.

1. 실제 GPT에 기존 누끼를 유지하고 베이지 배경·부드러운 조명 단계를 추가해 달라고 요청했다.
2. 수정안 생성 후 기존 8노드·6연결은 유지됐다. 수정안은 추가 5개·수정 4개·삭제 0개, 예상 9회 요청을 표시했다.
3. 적용 후 13노드·12연결이 됐다. 입력 사진 3장, 기존 결과 폴더, 별도 광고 명령은 유지됐다. 기존 누끼 명령 문자열도 유지됐다.
4. 되돌리기를 눌러 8노드·6연결, 원래 명령과 미리보기 3장으로 복원됐다.
5. 실제 구성 요청을 시작한 뒤 취소했다. 8노드·6연결이 유지되고 수정안은 나타나지 않았다.
6. 실제 GPT에 누끼 프롬프트의 라벨 보존 조건만 강화하도록 요청했다. 단계 추가·삭제 없이 수정안이 생성됐다. 수정안 버리기 후 원래 8노드·6연결과 미리보기 3장이 유지됐다.
7. 결과 화면에서도 기존 예제 폴더에 3장이 남아 있음을 확인했다.

실제 GPT 구성 요청과 적용·되돌리기·취소·버리기를 확인했다. 이 검증에서는 새 이미지 생성 요청을 실행하지 않았다. 예상 9회는 사진 3장 × 이미지 작업 3단계의 계산이다.

## 검사 결과와 증거

- `npm run build`: 성공, TypeScript 통과.
- `node --test --test-reporter=dot tests/*.test.cjs bridge/tests/*.test.js`: 109개 통과, 종료 코드 0.
- 신규 테스트 9개: 문맥에서 픽셀 제외, 입력 및 기존 ID 유지, 다른 플로우 보존, 오래된 수정안 거절, 되돌리기, 잘못된 그래프 거절, 단계 순서, 단계 삭제 후 연결, 요청 중복·취소.
- 320/390/768/1280px: 문서 너비와 뷰포트 너비 일치, 수정 패널 1개, native select 0개. 모바일 버튼 높이 최소 44px.
- `review.png`, `applied.png`, `undone.png`, `cancelled.png`, `final-review.png`, `discarded.png`, `viewport-*.png`는 실제 화면 캡처다.
- 배포 전 구빌드 청크 로딩 오류가 한 번 기록됐다. 웹 재시작과 새로고침 후 위 기능을 검증했다. 공개 링크 HTTP 200.

새 모듈은 그래프 수정 준비·적용 안전성(workflow-edit)과 수정안 UI(workflow-edit-panel)를 각각 담당한다. 응답은 기존 계획·백업 파서로 읽는다. 새 의존성이나 타입 오류 억제를 추가하지 않았다. 되돌리기는 현재 페이지의 마지막 자연어 수정 한 번에 대해 제공하며, 재접속까지 유지되는 별도 버전 저장 기능은 포함하지 않는다.
