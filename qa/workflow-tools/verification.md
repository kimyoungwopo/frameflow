# Frameflow 작업 재사용 개선 검증

검증일: 2026-10-08

## 구현

- 오른쪽 패널의 시각적 작업 카드: 배경 제거, 배경 변경, 광고 연출. AI 예시 이미지임을 표시하고 기존 작업을 지우지 않고 새 공통 플로우로 추가한다.
- 내 작업 템플릿: 선택 그룹, 선택 노드가 속한 플로우, 또는 전체 작업 구조를 저장한다. 이름 변경·삭제·캔버스 삽입을 지원한다. 최대 30개이며 브라우저 localStorage에 설정만 저장한다. 이미지, 결과, 캐시, 계정 메타데이터 필드는 저장하지 않는다.
- 공통 스타일: 배경, 조명, 색감, 구도 비율. 프롬프트 노드로 연결해 이미지 요청에 반영한다. 기존 작업 설명을 보존한다. 설정 변경은 캐시 서명을 바꾼다. 누끼 작업에 불투명 배경을 함께 지정하면 안내하고 적용을 막는다.
- 결과 폴더의 이미지 선택: 전체 선택·개별 선택 후 다음 작업을 고른다. 최대 12장을 한 입력 노드로 복사해 새 그룹에 넣는다. 기존 결과는 보존하고 실행은 사용자에게 맡긴다.
- 그룹 선택 시 해당 그룹 위치로 캔버스를 이동한다.

## 자동 검증

- `npm run typecheck`: 통과.
- `node --test --test-reporter=dot tests/*.test.cjs bridge/tests/*.test.js`: 최종 수정 후 90개 통과, exit 0.
- `npm run build --prefix web`: 최종 수정 후 통과. Next.js TypeScript 검사 포함.
- 회귀 검증: 사진별 독립 요청, 누끼 투명 배경 요청, 템플릿 이미지·캐시 제외, 삽입 시 ID 재배정, 템플릿의 요청 설명 격리, 공통 스타일 요청 반영, 캐시 무효화, 템플릿·백업의 스타일 유지, 스타일이 기본 작업 설명을 덮어쓰지 않음.

## 실제 브라우저 검증

- 시각적 배경 변경 카드 → 4개 노드의 새 그룹 생성 → 이미지 두 장을 한 입력 노드에 업로드.
- 흰색 배경·부드러운 조명·4:5 구도를 적용 → 스타일 프롬프트 노드와 연결선 생성.
- 템플릿 저장 → 새로고침 → 저장된 템플릿 유지 → 새 그룹에 5개 노드 삽입. 입력 이미지는 비어 있으며 기존 그룹의 이미지 두 장은 유지됨.
- 기존 예제 결과 백업을 가져와 폴더의 향수·스킨케어 두 장 선택 → 광고 연출 선택 → 새 공통 입력의 두 이미지와 새 4개 노드 그룹 생성. 원본 결과 폴더의 세 이미지는 유지됨.
- 공개 링크에서 시각적 광고 작업 생성, 공통 스타일 적용, 템플릿 저장, 이미지 두 장 추가, 그룹 선택 이동 확인.
- 최종 빌드 공개 링크에서 390px, 768px, 1280px의 문서 너비가 각각 뷰포트와 같음. 390px 스타일 선택 컨트롤 높이 44px 확인.
- 작업 카드에서 Tab으로 이동 시 다음 카드에 키보드 포커스가 보임.
- 최종 공개 화면 콘솔 error 목록은 비어 있음.

## 화면 근거

- `public-desktop.png`: 최종 공개 빌드의 공통 입력, 스타일 노드, 작업 카드, 템플릿 및 스타일 진입점. 키보드 포커스 포함.
- `public-style-mobile.png`: 최종 공개 빌드 390px 전체 화면, 스타일 설정 및 여러 사진 입력.
- `public-tablet.png`: 최종 공개 빌드 768px 전체 화면.
- `results-selected.png`: 예제 결과 폴더에서 두 장 선택 및 광고 연출 후속 작업 설정.

## 한계 및 운영 확인

- 생성 요청은 자동 테스트의 제어된 실행 함수로 검사했다. 이 작업에서 유료/계정 기반 실제 AI 이미지 생성은 실행하지 않았다. 모델의 실제 스타일 일관성과 생성 품질을 입증한 자료는 아니다.
- 구도 비율은 모델에 전달하는 지시이며 정확한 출력 픽셀 비율을 강제하는 변환은 아니다. UI에 이 한계를 표시했다.
- 이 프로젝트는 기존 다크 테마만 제공한다. 별도의 라이트 테마를 추가하지 않았다.
- 예제 결과 폴더 이미지는 기존 데모 백업이며 이번 검증에서 새로 생성한 결과가 아니다.
- 웹 프로세스만 재시작했다. Bridge PID 68288 및 기존 Cloudflare 터널은 유지했다.
- 기존 임시 링크의 페이지 HTTP 200 및 계정 미연결 상태의 Bridge JSON 응답을 확인했다.

## 자체 검토

- 새 의존성 없이 기존 배치 실행·이미지 저장·결과 폴더·프로젝트 백업 구조를 재사용했다.
- 템플릿은 필드 목록으로 구조·설정만 추출하고 읽을 때 노드 유형과 연결을 검증한다.
- 스타일 노드와 일반 작업 지시를 실행 엔진에서 구분해 기본 요청의 누락을 방지했다.
- 후속 작업과 템플릿은 새 그룹으로 추가하며 다른 그룹의 노드·결과·전역 작업 설명을 덮어쓰지 않는다.
- 다중 스타일이 있는 범위에 새 공통 스타일을 적용할 때 범위의 이전 스타일 노드들을 하나로 교체해 중복 지시를 방지한다.
