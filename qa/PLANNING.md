# 자연어 플로우 검증 — 2026-10-07

현재 자동 구성은 PROVIDER_PLAN_URL 미설정 시 동작하는 로컬 규칙 방식입니다. GPT가 자유롭게 문장을 해석했다고 주장하지 않습니다. 생성·편집 provider 연결과 플로우 계획 provider 연결은 별개입니다.

## 발견 및 수정

- 배경을 묘사한 새 생성 요청을 IMAGE INPUT 편집으로 분류하던 문제.
- 배경 제거와 해상도 개선 중 한 단계만 구성하던 문제.
- 배경을 제거하지 말라는 부정 표현을 제거 명령으로 처리하던 문제.
- 사진 3장을 각각 처리하는 요청에 입력·PREVIEW 1개만 만들던 문제.
- 합성 후 해상도 개선, 생성 후 해상도 개선을 누락하던 문제.
- 제품 사진을 광고 이미지로 만들라는 요청을 새 생성으로 오분류하던 문제.
- COMMAND에 원래 요청을 보존하여 배경 제거 외 사용자 지시가 빠지지 않도록 수정.
- 저장 작업 복원 전 입력이 덮어써지는 경우를 확인하여 복원이 끝난 뒤 편집 UI 표시.
- 캔버스 축소 시 중심 기준으로 노드가 화면 밖으로 이동하던 문제: 좌측 상단 기준으로 수정.

## 검증

수정 전 새 회귀 테스트 7개 실패를 확인했고, 수정 후 통과했습니다. 전체 `npm test`: 40개 통과, 실패 0. `npm run typecheck` 통과. 최종 `npm run build`의 TypeScript 검사·컴파일·9개 페이지 생성 통과.

실제 localhost 계획 API에 11개 예시를 입력하고 반환된 그래프를 실제 실행 엔진으로 추적했습니다. 이미지 작업 함수는 합성 결과 문자열을 반환하도록 대체하여 유료 이미지 요청을 보내지 않았습니다. 입력 이미지 요구, 연속 작업의 앞선 결과 전달, 투명 배경 플래그, 분리된 PREVIEW, REPEAT 횟수를 확인했습니다. 상세 결과: planning-scenarios.json.

실제 브라우저에서 새 생성(3노드·2연결), 배경 제거 후 해상도 개선(5노드·4연결·예상2회), 사진3장 각각 배경 제거(12노드·9연결·예상3회), 제거하지 말고 선명도만 개선(IMAGE → UPSCALE → PREVIEW)을 확인했습니다. 최종 화면에서 입력 문장과 COMMAND에 원본 문장 보존을 확인했습니다. 390/768 가로 넘침 없음, 콘솔 error/warn 0개.
